# PyJet

[English](README.md) | **Русский**

[![PyPI](https://img.shields.io/pypi/v/pyjet3d.svg)](https://pypi.org/project/pyjet3d/)
[![Python](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://pypi.org/project/pyjet3d/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

`pyjet3d` — компактный 3D-растеризатор для Python без внешних зависимостей.
Он рисует low-poly геометрию на CPU в RGB565-фреймбуфер, поэтому для сцены не
нужны GPU, OpenGL, игровой движок или библиотека для создания окон.

Это привязки Python к [CubeCoders/Jet](https://github.com/CubeCoders/Jet) —
фиксированному C++17-растеризатору, рассчитанному на ограниченные устройства
и вполне пригодному для обычного десктопа.

## Возможности

- Полностью программный рендеринг; во время работы нужна только стандартная
  библиотека Python.
- Полноразмерный RGB565-вывод с буфером глубины, а также нативное чтение
  RGB888 и RGBA8888 без покадрового цикла преобразования на Python.
- Многопоточный тайловый растеризатор для десктопа: постоянный пул потоков,
  параллельная очистка и детерминированный результат. Отсечение объектов по
  пирамиде видимости выполняется до трансформации вершин и отправки в очередь.
- SSE2/AVX2-ядра для заливки спанов, очистки и нативного преобразования цвета
  на x86-64; на других платформах — скалярный запасной путь.
- Камера с позицией, поворотом, `lookAt()`, FOV и ближней/дальней плоскостями
  отсечения.
- Плоское затенение, Гуро, Фонг, каркасный и неосвещённый режимы.
- Направленный, окружающий и точечный свет в мировом пространстве с цветом
  по каналам и затуханием по диапазону.
- Треугольные меши, собираемые прямо из списков Python, с автоматическими
  нормалями граней или необязательными нормалями на вершину для гладкого
  затенения.
- Настройки отсечения граней, смешивания и буфера глубины для каждого меша.
- Чтение фреймбуфера как `bytes`, доступ к пикселям и статистика кадра.
- Колёса для Linux, Windows и macOS через `cibuildwheel`.

## Установка

```bash
python -m pip install pyjet3d
```

Требуется Python 3.9 или новее. Дополнительные пакеты во время работы не
нужны.

> **Переход на 0.3.0:** импорт переименован с `pyjet` на `pyjet3d`, чтобы
> избежать конфликта с посторонним проектом `pyjet` на PyPI. Замените
> `import pyjet` на `import pyjet3d`.

## Быстрый старт

```python
import pyjet3d

scene = pyjet3d.Scene(320, 240)

camera = pyjet3d.Camera()
camera.setPosition(0, 0, -500)
camera.setFOV(70, scene.width)   # FOV в градусах; ширина задаёт масштаб проекции
camera.nearPlane = 32
camera.farPlane = 4096
scene.setCamera(camera)

material = pyjet3d.Material(0xF800)  # ярко-красный в RGB565
material.shadingMode = pyjet3d.ShadingMode.FLAT

# Обход против часовой стрелки: лицевая грань при CULL_BACKFACES по умолчанию.
scene.addMesh(
    [(0, 120, 0), (120, -120, 0), (-120, -120, 0)],
    material,
)
scene.render()

# Во фреймбуфере width * height little-endian значений RGB565.
framebuffer = scene.get_framebuffer()
assert len(framebuffer) == scene.width * scene.height * 2

# Преобразуем в RGB888 и сохраняем PPM без сторонних библиотек.
rgb = pyjet3d.framebuffer_to_rgb(framebuffer, scene.width, scene.height)
with open("triangle.ppm", "wb") as out:
    out.write(b"P6\n%d %d\n255\n" % (scene.width, scene.height))
    out.write(rgb)
```

Это весь цикл: создать сцену, добавить геометрию, отрисовать и забрать
пиксели. Скрытого окна или цикла событий нет. Для вывода через Pillow:

```python
from PIL import Image

rgb = pyjet3d.framebuffer_to_rgb(
    scene.get_framebuffer(), scene.width, scene.height
)
Image.frombytes("RGB", (scene.width, scene.height), rgb).save("triangle.png")
```

Освещение необязательно и настраивается в той же сцене:

```python
sun = pyjet3d.DirectionalLight(
    azimuth=225, elevation=45, r=255, g=241, b=214, intensity=255
)
scene.setDirectionalLight(sun)
scene.setAmbientLight(pyjet3d.AmbientLight(100, 104, 120))
scene.addPointLight(
    pyjet3d.PointLight(-220, -80, -280, 255, 190, 120, 150, 900)
)
```

Точечный свет линейно затухает от `rangeMin` до `rangeMax` и учитывается
встроенными путями FLAT/GOURAUD/PHONG. Если в сцене нет ни одного источника
света, поверхности рисуются исходным цветом с полной яркостью; добавляйте
окружающий свет, если нужна подсветка затенённых участков.

## Производительность на десктопе

В Python-сборке включён десктопный тайловый растеризатор. `render()` делит
фреймбуфер на горизонтальные тайлы, очищает и растеризует каждый тайл в
постоянном пуле потоков, причём вызывающий поток тоже участвует в работе.
Отсечение объектов и трансформация вершин выполняются один раз в вызывающем
потоке до запуска пула, поэтому воркеры только читают неизменяемую очередь
рендера. Результат детерминирован: последовательный и многопоточный режимы
дают одинаковые пиксели и счётчики треугольников.

Размер пула по умолчанию адаптивный и ограничен восемью участниками, чтобы не
перегружать пропускную способность памяти. Его можно настроить:

```python
scene.thread_count = 0       # авто (по умолчанию)
scene.thread_count = 4       # четыре участника
scene.thread_count = 1       # классический однопоточный рендер
scene.threaded_rendering = False
```

В автоматическом режиме небольшие сцены и низкие разрешения остаются на
последовательном пути; пул включается, когда фреймбуфер достаточно велик или
в сцене много треугольников. Чтение `scene.thread_count` возвращает фактическое
число участников. `Scene` не поддерживает повторный вход: при использовании
нескольких потоков Python сериализуйте рендеринг и чтение фреймбуфера.
Очистка и заливка непрозрачных спанов используют SSE2 на любом x86-64 и AVX2
во время выполнения в сборках GCC/Clang с его поддержкой. Чтение фреймбуфера
доступно в трёх нативных форматах:

```python
raw565 = scene.get_framebuffer()          # 2 байта на пиксель, RGB565
rgb888 = scene.get_framebuffer_rgb888()   # 3 байта на пиксель, R G B
rgba   = scene.get_framebuffer_rgba8888() # 4 байта на пиксель, R G B 0xFF
```

`framebuffer_to_rgb()` и `framebuffer_to_rgba()` преобразуют существующую
строку RGB565 в нативном коде, поэтому при сохранении изображения цикл Python
не нужен.

## Что доступно из Python

`pyjet3d` — намеренно сфокусированная обёртка:

- **Scene** — размеры, камера, свет, добавление мешей, цвет фона, очистка,
  чтение фреймбуфера, доступ к пикселям и статистика кадров.
- **Camera** — позиция, поворот Эйлера, `lookAt()`, FOV и плоскости отсечения.
- **Mesh** — вершины, индексы треугольников, необязательные нормали на
  вершину, преобразования, отсечение, смешивание и флаги глубины. Геометрия
  копируется в сцену при `addMesh()`.
- **Material** — цвет RGB565, альфа, diffuse/specular/emissive и все режимы
  затенения.
- **Свет** — направленный, окружающий и точечный свет в мировом пространстве;
  все они учитываются встроенными режимами затенения.
- **Вспомогательные типы** — нативные `framebuffer_to_rgb()` /
  `framebuffer_to_rgba()`, а также `Vector3` и `Color`.

Текстуры, пользовательские шейдеры, спрайты, частицы, постобработка, picking
и нативные помощники для примитивов/OBJ есть в C++-движке, но не входят в
текущий Python API.

## Как это работает

Jet — растеризатор с фиксированным конвейером. Он преобразует вершины
целочисленной арифметикой с фиксированной точкой, отсекает треугольники, растеризует их
с необязательным буфером глубины и затеняет по данным материала и света.
Сборка Python настроена на полноразмерный десктопный вывод с буфером глубины,
освещением и тайловым пулом потоков; встраиваемая C++-сборка может быть урезана
под ESP32 и похожие платформы. Объекты отсекаются по пирамиде видимости до
трансформации вершин, поэтому невидимая геометрия не попадает в очередь
рендера.

Движок умеет гораздо больше, чем показывает Python-обёртка: текстуры,
инстансинг, спрайты, частицы, экранные эффекты и пользовательские шейдеры.
См. [нативную документацию](https://cubecoders.github.io/Jet/) и репозиторий
[JetExamples](https://github.com/CubeCoders/JetExamples).

## Разработка

Запуск тестов Python из корня репозитория:

```bash
python -m pytest
```

Локальная сборка колеса:

```bash
python -m pip install build
python -m build --wheel
```

Версия релиза хранится в [`version.txt`](version.txt) одной строкой, например
`v0.3.0`. Пуш, меняющий этот файл в `main`, запускает релизный workflow:
собираются колёса для Linux, Windows и macOS, создаётся или обновляется
соответствующий GitHub-релиз с прикреплёнными колёсами, а затем они
публикуются на PyPI. Подробности — в
[`.github/workflows/wheels.yml`](.github/workflows/wheels.yml).
